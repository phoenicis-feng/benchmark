# 江湾市 · 城市经营模拟

一款离线运行的浏览器城市经营游戏。人口迁移、住房密度、实际就业、道路通勤、水电供应、污染、公共服务和月度财政持续共同运行。完成四个经营目标后可以继续建设。

## 运行

直接用现代桌面浏览器打开 **`index.html`**，点击「开始经营」。这是包含全部 CSS、程序和绘图的独立 HTML，不需要安装、账号、网络或构建。可以复制该文件到其他电脑运行。

默认进入有道路、水电和第一批居民的起步小镇；通过右上角 **··· → 新建 · 空白地图**，可从唯一的区域入口开始建设。移动设备有适配布局，但精细规划推荐桌面浏览器。

也可在此目录执行 `python3 -m http.server 8765`，然后打开 `http://localhost:8765`。游戏不会在页面关闭期间继续模拟。

## 第一座城市

1. 点击住宅区，在已连通道路旁扩建住房，等待人口迁入。初期不必大规模增建昂贵设施。
2. 根据左侧 RCI 需求增加商业和工业，保证实际岗位足够；工业与发电站应远离住宅。
3. 从西侧固定区域入口延伸道路。建筑必须与道路上下左右相邻，斜角相邻无效；水面只能建桥。
4. 水电在各自的道路网络内供应，容量和连接缺一不可。用地图图层和地块检查定位停供地块。
5. 约 300 人后补建学校、诊所、公园和消防，并规划分散通勤的路网，支持更高密度。
6. 查看财政面板，调整税率和预算，使月度收入覆盖运行费用。每笔贷款获得 ¥10,000，36 个月每月还款 ¥360，最多同时持有 3 笔。

## 模拟规则

- **道路与就业：**道路和桥梁组成连通图。每户 55% 的居民进入劳动力市场，取整后按可达的最短道路路径寻找剩余岗位。就业不会超过劳动力和有效岗位容量；没有可达工作时，住宅不吸引新居民。西侧入口是迁入和分区发展的必要连接。
- **交通：**每位在岗居民产生 2 单位往返车流，叠加到实际路径。道路标准承载量是 60 × 道路预算比例。使用道路上的平均超载比例表示全城拥堵；拥堵降低幸福度，并令工商收入最多减少 25%。通勤超过 12 格还会额外降低该住宅的幸福度。这里模拟的是按月汇总的通勤流，不是逐车交通物理。
- **住房与岗位：**低 / 中 / 高密度住宅容纳 40 / 85 / 150 人，商业提供 20 / 45 / 85 岗位，工业提供 35 / 70 / 130 岗位。新分区有入口连接且水电覆盖超过 80% 后自动开发。每 6 个月检查升级：住宅入住率 > 80%、幸福度 > 64、教育覆盖 > 20%、住宅需求为正；产业利用率 > 75%、相应需求为正。升级由开发商承担，不额外扣除市政资金。
- **水电：**发电站基础容量 1,500，供水站 1,800，随预算调整。住宅按人口耗用，工商业按岗位容量耗用，公共设施有固定基础负荷。工业用水是同规模用电负荷的 1.4 倍。每个道路网络独立按比例分配，缺水或缺电减少有效岗位，并阻碍入住。道路同时抽象市政管网，无需单独铺电线或管道。
- **公共服务：**公园、学校、诊所、消防按距离衰减，需要与住宅同属一个道路网络，且受自身水电与服务预算影响。全城服务覆盖按居民人数加权。学校支持密度升级；医疗和公园提高幸福度；消防降低火灾风险。设施维护费用抽象包含市政人员成本。
- **污染：**工业密度和发电站产生距离衰减的污染，降低附近住宅幸福度。绿地公园提高吸引力，但不会凭空清除工业污染。
- **迁移：**可达岗位空余、水电、税率和幸福度共同决定迁入。停供、高失业或极低幸福度引发迁出。人口不超过可用住房。负资金暂停迁入，并额外导致人口流失，仍可用财政调整和贷款恢复经营。
- **月度财政：**居民税 = 人口 × 税率 × 0.15；工商税 = 在岗人数 × 税率 × 0.21 × (1 − 拥堵比例 × 0.25)。按实际设施与预算扣除维护费用和到期前的贷款还款。建造费用立即扣除，森林格另收 ¥15 清理费，拆除费 ¥20。税率范围 3–18%，预算范围 20–150%。
- **事件：**每 3 个月按消防覆盖检查火灾，受损建筑停用 3 个月并自动修复，住宅居民撤离城市。可通过 ··· 关闭火灾。随机数种子包含在存档中，恢复后模拟可复现。

## 经营目标

| 目标 | 达成条件 | 一次性奖励 |
| --- | --- | --- |
| 小镇初成 | 人口 ≥ 150 | ¥1,500 |
| 自给自足 | 人口 ≥ 300、月度盈利、失业 < 15% | ¥2,500 |
| 宜居城市 | 人口 ≥ 800、幸福度 ≥ 65、拥堵 < 35% | ¥5,000 |
| 江湾都会 | 人口 ≥ 2,000、幸福度 ≥ 70、月度盈利 | ¥8,000 |

目标按每月实际结算检查，奖励只发放一次。完成后继续自由经营；城市可能再次遇到拥堵、供给不足、衰退和财政问题，需要持续管理。

## 存档

每 3 个模拟月、切到后台和离开页面时自动保存，也可使用「保存」。重新打开页面会读取本浏览器存档，并暂停等待操作。

通过 **··· → 导出存档** 下载 JSON；**导入存档** 验证并恢复。导入、新建和读取前有明确的替换提示。建议定期导出备份，特别是在使用 `file://` 直接打开或无痕浏览时。存储被浏览器禁用时可以继续游戏并导出文件。

`tests/metropolis.json` 是正常付费建设产生的验收城市存档，可在游戏中导入观察大城市；不会默认加载。

## 源码与测试

- `engine.js`：独立的确定性模拟内核，同时供浏览器和 Node 测试使用。
- `ui.js`：建造操作、等距 Canvas 绘图、月度时钟、面板、图表和本地存档。渲染与模拟结算分开。
- `template.html` / `style.css`：页面与响应式布局。
- `build.mjs`：将以上文件内联到独立 `index.html`。
- `tests/engine.test.cjs`：24 项逻辑及长期运行测试。
- `tests/progression.cjs`：付费建设、扩容与目标达成验收；不注入人口或资金。
- `tests/browser.cjs`：14 项 Chromium 实际浏览器操作验收，直接加载离线 HTML。
- `tests/performance.cjs`：12,000 人规模的月度模拟耗时检查。

Node.js 18 或更新版本即可执行逻辑测试和构建：

```sh
npm test
npm run build
node tests/progression.cjs
node tests/performance.cjs
```

浏览器自动化需要 Playwright 和 Chromium；不会给游戏本身添加依赖：

```sh
npm install --no-save playwright
npx playwright install chromium
node tests/browser.cjs
```

如已安装 Playwright，可用 `PLAYWRIGHT_MODULE` 指定其绝对模块路径。详细实测范围、结果和截图见 `TEST_RESULTS.md`。
